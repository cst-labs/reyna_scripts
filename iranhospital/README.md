# ED Triage Pairwise Urgency Benchmark

Can an LLM tell which of two emergency-department patients is more urgent? This repo builds pairwise benchmarks from a real ED triage dataset (each patient has a ground-truth triage grade 1–5, where 1 is most urgent), asks different LLMs "which patient is more clinically urgent, A or B?", and measures accuracy against the grades.

The core experiment compares what the model is shown (chief complaint only vs. full vitals) and which model is asked (hosted frontier models vs. small local models).

## Data (`data/`)

| File | Contents |
|---|---|
| `ED_triage.csv` | One row per triage encounter: `triage_code`, age, gender, admission date parts, `ChiefComplaint` (ICD-10-style code), `NeedFastExecute`, `CriticalStatus`, `StuporStatus`, `PainGrade`, blood pressure, pulse, respiratory rate, temperature, O2 saturation, `AVPU`, and the ground truth `TriageGrade` (1–5). |
| `ED_admission.csv` | Admission/discharge info keyed by `triage_code`; supplies `PatientCode`. |
| `services/services1-10.csv` | Service-level records. Not used by any script. |
| `Tables Descriptions.docx` | Data dictionary. |

The data is not public; do not commit it.

## Method

1. **Cases.** Sample cases from the triage data. In the main benchmark, grades 1–4 are down-sampled to the size of grade 5 so every grade is equally represented (`balanced_cross_grade_cases.csv`, 85 cases, 17 per grade).
2. **Pairs.** Form pairs and randomly assign sides, so the correct answer (`winner`) is A or B with equal probability.
   - **Cross-grade pairs:** two patients with different grades. The more urgent one is the expected answer. 85 cases give 10 grade combinations × 17 × 17 = **2,890 pairs**.
   - **Same-grade pairs:** two patients with the same grade, used to measure agreement between models rather than accuracy.
3. **Prompt.** A "CT triage ranking assistant" system prompt requires a JSON reply: `{"chosen_patient": "A"|"B", "reasoning": "..."}`.
4. **Score.** `correct` is True when the pick matches the higher-urgency patient. Unparseable output counts as wrong and lowers the `json_valid` rate. Latency is recorded per call.

Complaint codes are translated to text with the `CHIEF_COMPLAINT_DESCRIPTIONS` map in `generate_balanced_cross_grade_pairs.py`. Codes not in the map are shown as `"<code> (description unavailable)"`.

## Prompt variants (the main independent variable)

| Variant | What the model sees | Scripts |
|---|---|---|
| **Chief-only** | age, gender, chief complaint | `pairwisetest_chief_only*.py` |
| **Full-fields (missing-aware)** | the above plus BP (sys/dia), pulse, respiratory rate, O2 sat, AVPU. Unrecorded values show as `missing`, and the prompt says not to read missing as normal or abnormal. | `pairwisetest_full_fields_missing*.py` |
| **Same-grade full-fields** | full-fields prompt on same-grade pairs | `pairwisetest_same_grade_full_fields*.py` |
| **Status-field ablation** | coded chart fields (PainGrade, vitals, AVPU) with or without `CriticalStatus`, `StuporStatus`, `NeedFastExecute` | `pairwisetest_ablation_20.py`, `pairwisetest_ablation_fixed_50.py` |

## Experiments

Experiments are listed in roughly the order they were run. Output CSVs are in `output/results/`.

### 1. Single-day prototype
`generatepairs.py` builds a first benchmark from one day of triage data, with exploratory prints and the first `pair_benchmark.csv`. It also produces `output/benchmarks/cases/benchmark_day.csv`.
`generatepairs_2017_05_09_all.py` redoes this for **2017-05-09**, producing all pairs for that day. `sample_2017_05_09_1000_pairs.py` samples 1,000 of them (seed 42).
`pairwisetest.py` ran this set against `azure.claude-opus-4-6` and `gpt-4.1-mini`.

### 2. Status-field ablation (hosted models)
`pairwisetest_ablation_20.py` asks whether the chart's coded status fields (`CriticalStatus`, `StuporStatus`, `NeedFastExecute`) leak the answer. It runs each pair twice, once `with_status_fields` and once `without_status_fields`. A first pass used 20 pairs (`opus-4.6`, `gpt-4.1-mini`).
`create_fixed_pair_sample_50.py` freezes a **fixed 50-pair sample** (seed 20260612) so models are directly comparable. `pairwisetest_ablation_fixed_50.py` ran it on claude-opus-4.5, claude-opus-4.6, gpt-5.1, gpt-5.2 and gpt-5.5. Results are in `output/results/statustest/`.

### 3. Latency benchmark
`measure_latency_by_model.py` times requests per model (`output/results/latency/`). `summarize_statustest_latency.py` summarises latency from the fixed-50 runs, split by with/without status fields.
Most calls take 1–5 s. Several GPT models show occasional ~60 s outliers (max ~62–65 s). `azure.claude-opus-4-7` returned errors on all 20 requests.

### 4. Balanced cross-grade benchmark (main experiment)
Generated by `generate_balanced_cross_grade_pairs.py` (a 100-pair sample) and `generate_balanced_cross_grade_all_pairs.py` (**all 2,890 pairs**, plus a `_full_fields` version enriched with vitals via `build_full_fields_pair_benchmark.py`).

Each prompt variant was run on every pair, with these models:

- **Hosted (OpenAI-compatible gateway):** `gpt-5.4` (`azure-gpt-5.4`) and `gpt-5.5`, run by `run_remote_gpt55_*.py`.
- **Local via Ollama:** `qwen3:1.7b`, `medgemma:4b`, `qwen2.5:7b`, `llama3.1:8b`, `gemma2:9b`, run by `run_local_ollama_*.py`.
- **Local via HuggingFace transformers:** `mistralai/Ministral-8B-Instruct-2410` and `WeiboAI/VibeThinker-3B`, run by `run_local_exact_hf_*.py`.
- **Phi-3.5-mini:** `run_phi35_server_chief_only.py` targets a local OpenAI-compatible server on port 8000. Its result file is only 727 bytes, so it looks like a short trial.

The `*_all_pairs.py` runners use the full 2,890 pairs. The shorter variants use the 100-pair sample.

### 5. COVID-19 filter
`filter_non_covid_all_pairs_benchmarks.py` removes every pair that involves a COVID-19 (`U07.1`) patient. This drops **529 of 2,890 pairs and leaves 2,361**, in both the chief-only and full-fields benchmarks (`output/benchmarks/pairs/non_covid/`). The non-COVID set is used for the headline numbers. (The scripts don't state why COVID was excluded, so the rationale is yours to fill in.)

Accuracy on the 2,361 non-COVID cross-grade pairs (from `output/analysis/non_covid/non_covid_all_pairs_model_summary.txt`):

| Model | Chief-only | Full-fields |
|---|---|---|
| azure-gpt-5.4 | 0.758 | 0.742 |
| gemma2:9b | 0.659 | 0.700 |
| medgemma:4b | 0.704 | 0.644 |
| Ministral-8B-Instruct-2410 | 0.643 | 0.650 |
| qwen2.5:7b | 0.679 | 0.577 |
| llama3.1:8b | 0.623 | 0.532 |
| qwen3:1.7b | 0.615 | 0.335 |

Findings visible in these outputs:
- gpt-5.4 is best, at 0.74–0.76.
- Adding vitals did **not** reliably help. Only gemma2:9b and Ministral-8B improved (by 0.04 and 0.01).
- qwen3:1.7b fell from 0.615 to 0.335. Its JSON-valid rate dropped from 2,112 to 1,214 of 2,361 outputs, so much of that loss is invalid output rather than wrong answers.
- Ministral-8B is much slower than the other local models (12–18 s per call, versus about 1–2 s).

### 6. Error analysis by grade gap
`analyze_non_covid_errors_by_grade_gap.py`, `summarize_non_covid_by_model_gap.py` and `analyze_cross_grade_by_grade_pair.py` break accuracy down by grade gap (1–4) and by specific grade pair (outputs in `output/analysis/non_covid/` and `output/analysis/cross_grade_by_grade_pair/`).
- Accuracy rises with grade gap for essentially every model. For gpt-5.4 on chief-only it goes from 0.66 (gap 1) to 0.87 (gap 4). The hard cases are adjacent grades, especially 3 vs 4.
- `compare_cross_grade_prompt_families_all_pairs.py` compares chief-only and full-fields side by side (`cross_grade_prompt_family_comparison/`).
- `filter_*_wrong_pairs*.py` write per-model CSVs of wrong or invalid pairs for manual review (`chief_only_wrong_pairs_all_models/`, `full_fields_wrong_pairs_all_models/`, `gpt54_wrong_pairs/`).

### 7. Same-grade agreement
For same-grade pairs there is no correct answer, so the question is whether models agree with each other. `analyze_same_grade_model_agreement*.py` builds a model-by-model agreement matrix and per-pair consensus. `render_same_grade_agreement_report*.py` renders the report. Results for this experiment are in `output/results/pairwise/*same_grade_full_fields*`.

### 8. Feature analysis
`analysisfields.py` relates `TriageGrade` to each field (count and percentage crosstabs and heatmaps for `NeedFastExecute`, `CriticalStatus`, `StuporStatus` and `AVPU`; per-grade summaries and a correlation heatmap for the numeric vitals; and missingness). Outputs are in `output/analysis/feature_analysis/`.

## Layout

```
data/                     raw data (not public)
output/
  benchmarks/
    cases/                sampled patients
    pairs/                pair benchmarks (non_covid/ = filtered)
  results/
    pairwise/             raw per-pair model outputs
    statustest/           fixed-50 status-field ablation
    latency/              latency measurements
  analysis/               summaries, reports, wrong-pair extracts
  scripts/
    generate*.py, build_full_fields_pair_benchmark.py    build benchmarks
    pairwisetest*.py                                     evaluation engines (prompts, parsing)
    analyze_same_grade_*.py, compare_cross_grade_*.py    top-level analyses
    runs/                                                model-specific runners
    filters/, reports/, samples/                         post-processing and sampling
    parameters.py                                        exploratory data prep
```

Run everything from the **repository root**, because paths such as `data/ED_triage.csv` and `output/...` are relative. Set `PYTHONPATH=output/scripts` so the scripts can import each other. Top-level scripts run directly; those in `runs/`, `filters/`, `reports/` and `samples/` run as modules:

```bash
export PYTHONPATH=output/scripts
python output/scripts/generate_balanced_cross_grade_all_pairs.py
python -m runs.run_local_ollama_chief_only_all_pairs     # needs `ollama serve`
python -m filters.filter_non_covid_all_pairs_benchmarks
python -m reports.summarize_non_covid_all_pairs_models
```

## Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt     # pandas openai seaborn matplotlib torch transformers
```

Create a `.env` (gitignored) with the gateway credentials: `AITECH_API_KEY`, `LITELLM`, `LITELLM_BASE_URL`. Hosted-model runners read these. Local runners need Ollama on `localhost:11434`, or the HuggingFace weights for the `local_hf` runners.

## Caveats

- The benchmark has only 85 distinct patients. The 2,890 pairs are combinations of them, so they are not independent samples.
- `gpt-5.5` has low valid-choice rates in the prompt-family comparison (0.50 chief-only, 0.42 full-fields). Its accuracy there likely reflects incomplete or failed runs rather than model quality, so treat it with caution.
- `WeiboAI/VibeThinker-3B` is missing from the non-COVID accuracy table above; I didn't verify its result coverage.
- Accuracy figures for the 2017-05-09 runs, the status-field ablation and the same-grade agreement runs are not quoted above. Read them from the CSVs.
- The Phi-3.5-mini run's purpose is inferred from its tiny output file, not documented.
- `grade_pair_overall_summary.csv` reports `total_pairs = 2023` per grade pair. That is 289 pairs × 7 models, not 2,023 distinct pairs.
